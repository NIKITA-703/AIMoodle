# MoodleBot

Бот для прохождения тестов в Moodle с помощью Selenium и локальной языковой модели через OpenAI-совместимый API LM Studio.

Бот находит активные курсы и тесты, загружает связанные лекции, извлекает текст из HTML/PDF, решает вопросы, проверяет результат через обзор Moodle и сохраняет подтвержденные ответы для следующих попыток.

## Возможности

- авторизация в Moodle;
- поиск курсов со статусом `Проходите сейчас` и `Пересдача`;
- продолжение незавершенной попытки;
- обнаружение тестов с оценкой ниже проходной;
- автоматическое перепрохождение после разбора предыдущей попытки;
- защита последней доступной попытки;
- поддержка `radio`, `checkbox`, `text` и `select`;
- обработка нескольких вопросов на одной странице;
- загрузка HTML-лекций и PDF;
- объединение лекций из нескольких частей (`1.1`, `1.2`, `1.3` и т. д.);
- общий контекст сохраненных лекций для итогового теста;
- память подтвержденных ответов из обзора Moodle;
- статистика запусков, попыток и отдельных вопросов в SQLite;
- последовательная и параллельная обработка курсов.

## Требования

- Windows 10/11;
- Python 3.11 или новее;
- Google Chrome или Chromium;
- LM Studio с загруженной моделью;
- доступ к Moodle.

Проект проверялся с Qwen3 14B и контекстом 32768 токенов.

## Установка в Git Bash

Перейдите в папку проекта:

```bash
cd "/d/Visual Studio Code/AIAgent"
```

Создайте виртуальное окружение:

```bash
python -m venv .venv
source .venv/Scripts/activate
```

Установите зависимости:

```bash
python -m pip install --upgrade pip
pip install -r requirements.txt
```

Создайте локальный файл настроек:

```bash
cp .env.example .env
```

## Настройка LM Studio

1. Загрузите модель в LM Studio.
2. Откройте раздел локального сервера.
3. Запустите OpenAI-совместимый API.
4. По умолчанию бот ожидает сервер по адресу `http://localhost:1234`.

До открытия Chrome бот проверяет, что API доступен и модель загружена. Если LM Studio выключен, запуск останавливается без расходования попытки Moodle.

## Настройка `.env`

Пример:

```env
LOGIN=your_login
PASSWORD=your_password

# Оставьте пустым при обычной установке Chrome.
CHROME_BINARY_PATH=

LM_STUDIO_BASE_URL=http://localhost:1234

# Общий максимум отправленных попыток за один запуск.
TESTS_LIMIT=1

# Число разных курсов, обрабатываемых одновременно (1-4).
PARALLEL_WORKERS=1

# Необязательно: точное имя или уникальная часть имени курса.
TARGET_COURSE=

# Кэш курсов без доступных тестов.
COURSE_CACHE_DAYS=30
REFRESH_COMPLETED_COURSES=false

# Разрешать автоматическое использование последней попытки.
AUTO_USE_LAST_ATTEMPT=false

# Запрещать новый тест, если контекст лекции не найден.
REQUIRE_LECTURE_CONTEXT=false
```

### Параметры

| Параметр | По умолчанию | Назначение |
|---|---:|---|
| `LOGIN` | пусто | Логин Moodle |
| `PASSWORD` | пусто | Пароль Moodle |
| `CHROME_BINARY_PATH` | пусто | Путь к нестандартной сборке Chrome/Chromium |
| `LM_STUDIO_BASE_URL` | `http://localhost:1234` | Адрес API LM Studio |
| `TESTS_LIMIT` | `1` | Общий лимит отправленных попыток за запуск |
| `PARALLEL_WORKERS` | `1` | Количество одновременно обрабатываемых разных курсов |
| `TARGET_COURSE` | пусто | Точное имя или уникальная часть имени выбранного курса |
| `COURSE_CACHE_DAYS` | `30` | Срок хранения статуса отсутствия доступных тестов |
| `REFRESH_COMPLETED_COURSES` | `false` | Принудительная перепроверка кэша курсов |
| `AI_MAX_CONCURRENT_REQUESTS` | `1` | Максимум одновременных запросов к LM Studio |
| `AI_RESPONSE_ATTEMPTS` | `2` | Повторы нераспознанного ответа модели |
| `AI_ENABLE_THINKING` | `false` | Включение длинных рассуждений Qwen3 перед ответом |
| `AUTO_USE_LAST_ATTEMPT` | `false` | Разрешение автоматически расходовать последнюю попытку |
| `REQUIRE_LECTURE_CONTEXT` | `false` | Требование обязательного контекста лекции |

Файл `.env` содержит учетные данные и исключен из Git.

## ChromeDriver

Указывать `CHROMEDRIVER_PATH` не требуется. Selenium Manager автоматически использует совместимый ChromeDriver.

Алгоритм запуска:

1. Selenium пытается использовать драйвер из локального кеша.
2. Если он не подходит, Selenium Manager пытается найти или скачать актуальную версию.

Для автоматического обновления необходим доступ к интернету. При работе без интернета в кеше уже должен находиться совместимый драйвер.

## Запуск

Активируйте окружение:

```bash
source .venv/Scripts/activate
```

Запуск с настройками из `.env`:

```bash
python main.py
```

Показать аргументы:

```bash
python main.py --help
```

Показать анализ уже накопленных результатов без запуска Chrome:

```bash
python main.py --stats-report
```

Отчёт группирует оценённые Moodle вопросы по источнику ответа, типу вопроса и режиму контекста лекции.

### Последовательный режим

```bash
python main.py --workers 1 --tests 5
```

Один браузер последовательно обрабатывает курсы. Это наиболее стабильный режим для одной локальной GPU и больших лекций.

Обработать только указанный курс:

```bash
python main.py --workers 1 --tests 3 --course "Архитектура информационных систем ч.2"
```

Явно выбранный курс проверяется даже при наличии записи `tests_complete`. Для перепроверки всех ранее пропущенных курсов используйте:

```bash
python main.py --workers 2 --tests 5 --refresh-courses
```

### Параллельный режим

```bash
python main.py --workers 2 --tests 10
```

Координатор выбирает два разных курса, после чего каждый worker запускает отдельный Chrome и остается внутри назначенного курса.

`--workers` и `--tests` временно переопределяют значения из `.env`, но сам файл не изменяют.

> `--tests` означает количество **отправленных попыток**, а не уникальных или успешно пройденных тестов. Перепрохождение проваленного теста также расходует этот лимит.

Для Qwen3 14B на одной GPU рекомендуется не больше двух worker. Два одновременных длинных запроса делят ресурсы GPU и могут оказаться медленнее последовательного режима.

По умолчанию два браузера работают параллельно, но обращения к одной локальной модели выполняются последовательно (`AI_MAX_CONCURRENT_REQUESTS=1`). Это защищает общий KV-кэш LM Studio от повреждения при одновременной генерации. Увеличивайте значение до `2` только после проверки стабильности модели.

Первое нажатие `Ctrl+C` запрашивает безопасную остановку: текущий HTTP-запрос завершается, тест не отправляется, браузеры закрываются. Повторное `Ctrl+C` немедленно завершает процесс без ожидания очистки.

## Жизненный цикл запуска

1. Загружаются `.env` и статистика.
2. Проверяется LM Studio и наличие загруженной модели.
3. Создается запись запуска в SQLite.
4. Chrome открывает Moodle и выполняет авторизацию.
5. Координатор находит активные курсы и доступные тесты.
6. Для теста ищется одна лекция или все части соответствующей темы.
7. Перед новой попыткой бот читает обзоры предыдущих попыток.
8. Подтвержденные Moodle ответы сохраняются в память.
9. Бот продолжает существующую попытку или запускает новую.
10. Вопросы решаются из памяти, по лекции или на общих знаниях модели.
11. Тест отправляется, результат и ответы считываются из обзора.
12. Если балл ниже проходного, worker повторяет тест при наличии безопасной попытки и общего лимита.
13. После успешного результата worker берет следующий тест своего курса.
14. Когда тестов в курсе больше нет, worker записывает `tests_complete` в SQLite и завершает работу.

## Работа с лекциями

Поддерживаются:

- Moodle Page;
- Moodle Lesson;
- Resource;
- HTML;
- PDF;
- внешние материалы, доступные через Moodle.

Если тест имеет номер `1`, бот может объединить:

```text
Лекция 1
Лекция 1.1
Лекция 1.2
Лекция 1.3
...
```

Для теста `1.2` выбирается точная часть `1.2`. Дополнительная литература с текстом вроде `ч.1` не считается лекцией только из-за присутствия цифры.

Для итогового теста бот объединяет последние уникальные `.txt`-материалы, уже сохраненные в папке курса. Отсутствующие или еще не загруженные лекции автоматически там не появляются.

Полный многосотстраничный текст не отправляется модели для каждого вопроса. Из общего текста выбираются наиболее релевантные фрагменты размером до 18000 символов.

Ответ LM Studio ограничен JSON Schema. По умолчанию Qwen3 получает `/no_think` и лимит 300 токенов. Первый запрос использует точечную выборку из лекции, повторный запрос расширяет её с 18 000 до 36 000 символов. Если модель не сформировала допустимый ответ после настроенного числа повторов, бот останавливает попытку без случайного выбора и без отправки теста.

Сохраненные материалы находятся в:

```text
HTML Courses/<название курса>/
```

## Память ответов

После отправки теста бот открывает обзор Moodle и сохраняет:

- текст и идентификатор вопроса;
- выбранные варианты;
- правильные и неправильные варианты, если Moodle их показывает;
- балл за вопрос;
- тип вопроса;
- номер просмотренной попытки.

Основной ключ сопоставления — Moodle `qid`, поэтому перемешивание порядка вопросов не ломает память.

Файл памяти:

```text
data/quiz_memory.json
```

Полный ответ для checkbox подтверждается только при достаточных данных обзора. Частичный балл не считается доказательством полного набора правильных вариантов.

## Защита попыток

Рекомендуемая настройка:

```env
AUTO_USE_LAST_ATTEMPT=false
```

В этом режиме бот не начинает последнюю повторную попытку автоматически. Если попытка уже запущена, бот продолжает ее, чтобы она не завершилась пустой по таймеру.

При недостаточном балле бот:

1. открывает обзор;
2. сохраняет подтвержденные ответы;
3. возвращается в тот же тест;
4. использует память при повторном прохождении;
5. останавливается перед последней попыткой, если она защищена.

## Статистика

SQLite хранит версии алгоритмов отдельно от результатов:

```text
bot_versions -> runs -> attempts -> question_results
```

Для каждого нового запуска записываются версия бота, Git-коммит, состояние рабочей копии, версии памяти и поиска контекста, модель LM Studio и параметры запуска. Старые записи автоматически связываются с версией `legacy/unknown`.

Номер структуры SQLite хранится в `PRAGMA user_version`, поэтому следующие изменения схемы можно выполнять как последовательные миграции.

Использованный лекционный контекст связан с попыткой через таблицы `lecture_contexts` и `attempt_lecture_contexts`. В БД сохраняются только SHA-256, размер и количество объединённых материалов. Полные тексты остаются в `HTML Courses` и в SQLite не копируются.

SQLite-база:

```text
data/bot.db
```

В ней сохраняются:

- запуски и время работы;
- успешные, неудачные и прерванные попытки;
- оценки и проходные баллы;
- источник ответа: `memory`, `lecture`, `general_knowledge`;
- результаты отдельных вопросов;
- время ответа модели;
- подтвержденные правильные и неправильные варианты.

Краткая история результатов также записывается в:

```text
data/bot_history.log
```

## Тесты проекта

Запуск всех автоматических тестов:

```bash
python -m pytest -q
```

Тесты покрывают:

- HTML/PDF-контекст;
- выбор релевантных фрагментов лекции;
- лекции из нескольких частей;
- radio, checkbox и текстовые ответы;
- разбор обзора Moodle;
- память ответов;
- параллельную запись JSON/SQLite;
- общий лимит попыток и повторное прохождение.

## Частые проблемы

### Локальный ИИ недоступен

```text
Локальный ИИ недоступен
No models loaded
```

Запустите сервер LM Studio и загрузите модель.

### Chrome запускается долго

Selenium Manager может проверять или скачивать ChromeDriver. При проблемах сети он пытается использовать версию из кеша.

### Ошибка авторизации

Проверьте `LOGIN` и `PASSWORD` в `.env`. Бот ожидает переход на URL, содержащий `/my/`.

### PDF не читается

Обновите зависимости:

```bash
pip install -U pypdf cryptography
```

### Итоговый тест решается долго

Итоговый контекст строится из всех сохраненных лекций курса. Для одной GPU используйте:

```bash
python main.py --workers 1 --tests 1
```

## Ограничения

- селекторы зависят от текущей верстки и темы Moodle;
- бот обрабатывает тесты, но не загружает Word, презентации и другие ручные задания;
- итоговый контекст использует только ранее сохраненные материалы курса;
- качество ответа зависит от модели, содержания лекции и обратной связи Moodle;
- параллельный режим не гарантирует ускорение на одной GPU.
